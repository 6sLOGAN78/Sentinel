## Phase Goal

**As an** operator, **I want to** see pipeline health and have failure and scale behavior proven by tests and a reproducible benchmark report, **so that** reliability and performance are demonstrated rather than claimed.

<objective>
First failure-suite slice. This plan adds the missing spec §15 failures:
- a real Kafka broker restart (stop/start, not pause)
- ClickHouse outage recovery, both within and beyond the retry budget
- graceful SIGTERM mid-batch

They are combined with the existing writer-crash, DLQ, SSE-reconnect and rate-limit families into one named, nonempty-guarded selector, `scripts/check-chaos.sh`. Compose gets `stop_grace_period: 40s`. A reusable read-only resource gate, `scripts/check-resources.sh`, is added.

**Resource floor (user decision, RESOLVED):**
- Chaos and real-container integration runs require ≥ 10 GiB free on the filesystems holding the repo and Docker data (`docker info --format '{{.DockerRootDir}}'`, /var/lib/docker on this host).
- MemAvailable must be ≥ 3 GiB. Justification: the testcontainers set used by these suites (Kafka ~1 GiB heap+page cache, ClickHouse ~1 GiB, PostgreSQL ~0.2 GiB, Redis ~0.05 GiB), plus the Go toolchain building integration binaries (~0.5 GiB), totals about 2.75 GiB. 3 GiB leaves a small margin without demanding the ~4 GiB the host had free at research time.
- Below the floor the gate refuses with a message naming the measured value, the floor and "Sentinel will not prune; free space yourself". The agent never prunes.

Purpose: REL-02 and REL-03. `make test-integ` keeps its 32 m ceiling unchanged. The chaos selector is separate. Its `make test-chaos` target is added in 05-17, because the Makefile is owned by pending Phase 4 plan 04-16.

Out of scope here: the slow-consumer lag and overload-bounded families are added in 05-11, because they need the lag metrics from 05-05.

**Same-module execution note:** 05-05 (kafkax/telemetry/writers), 05-06 (logger/middleware/go.mod) and 05-08 share wave 2. This plan's integration tests compile against packages that 05-05 and 05-06 edit. With `use_worktrees: false`, run the wave-2 Go plans sequentially in the order 05-05 → 05-06 → 05-07 (05-08 is Python-only and may run in parallel), or use separate worktrees.

Safety: all containers are testcontainers-owned and disposable. Nothing touches the `sentinel` or `sentinel-p4-demo-20261024` stacks. Only the dedicated fault broker is stopped, never the TestMain broker.
</objective>
