# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope and sources

Frontend scope covers two surfaces:

1. **UI-05:** a new System page at `/system` showing pipeline and consumer health, ingest throughput, consumer lag, detection delay, write latency, DLQ and errors, with an optional Grafana link.
2. **UI-01 completion:** the Overview "Consumer lag" placeholder (`web/src/pages/Overview.tsx`, last `<p>`) is replaced with real position-based lag from the same System endpoint.

Grafana dashboards (OBS-05) are provisioned config-as-code under `observability/grafana/`. They are not governed by this contract. The System page only links to them.

Sources:
- `04-UI-SPEC.md` (approved design system; reused unchanged)
- `web/src/styles.css`, `App.tsx`, `Overview.tsx` (actual tokens and patterns)
- `05-RESEARCH.md` Pattern 5 (`GET /api/v1/system`, fixed PromQL allowlist, per-field "unavailable", admin-only recommendation) and the metric map in Pattern 1
- REQUIREMENTS UI-05, UI-01, UI-06 and OBS-02
- Spec §18 DoD (no invented numbers)

Mode: `--auto`, no CONTEXT.md. Every open choice is resolved by a documented default. See **Assumptions** at the end.

## Layout and navigation

**Navigation**
- Add a fifth sidebar link **"System"** → `/system` after Rules. It uses the same `.app-nav a` style, `aria-current="page"` handling and pushState navigation as the existing links.
- The link renders **only when the server-verified `session.role === "admin"`**.
- `App.tsx` routes `path === "/system"` to `<System key={session.generation} />` for every role. A non-admin who deep-links or refreshes on `/system` gets the forbidden state. They are not silently redirected.

**Page structure** (top to bottom, inside existing `<main>`; max-width 1440px, 24px padding, 16px at <600px)

1. **Header block**
   - `<h2>` "System" (28px/600)
   - Description paragraph in `.page-description` muted text
   - Toolbar row (flex, wrap, 16px gap) containing:
     - "Updated" line: `<time>` with the server `observed_at`, rendered as UTC `HH:MM:SS UTC`, 14px muted
     - **"Refresh system status"** button (primary, accent fill)
     - Optional "Open Grafana dashboards" link
2. **Pipeline status summary**
   - This is the primary visual anchor: the first panel, with a 20px/600 headline and a status badge.
   - Exactly one headline from the copy table:
     - "All services ready"
     - "{n} of {m} services not ready"
     - "Service health unavailable"
   - It is followed by a single-line sentence counting restarts in the last 15 minutes, or "Restart count unavailable".
3. **Services** (`<h3>` 20px/600)
   - Table columns: Service | Replicas (up / expected) | Readiness | Restarts (15 min).
   - Rows in fixed order: ingest, event-writer, detector, alert-writer, query-api.
   - The service name cell is `<th scope="row">` in `.identifier`.
4. **Throughput and errors** (`<h3>`)
   - Card grid holding:
     - Ingest events/s (total), with an adjacent `<dl>` breakdown by result: Accepted, Rejected, Rate limited, Shed, Unavailable
     - HTTP error ratio, with a breakdown: 5xx, 429, 503
     - DLQ events/s
5. **Consumer lag** (`<h3>`)
   - Table columns: Consumer group | Lag (records).
   - Rows: event-writer, detector, alert-writer.
   - A caption line explains the measure: "Position-based: end offset minus next unprocessed offset, maximum across partitions."
   - No color thresholds. Raw numbers only.
6. **Latency** (`<h3>`)
   - Cards for Detection delay p95 (5 min) and ClickHouse write p95 (5 min).
7. **Footnote** (14px muted)
   - "Values come from Prometheus with fixed server-side queries. Use Grafana for history."

**Grid and breakpoints**
- Cards use `display:grid; grid-template-columns: repeat(auto-fit, minmax(240px, 1fr)); gap: 16px`. This gives 3 to 4 columns at 1440px, 2 at 768px and 1 at 375px.
- Each card is `.surface` white with a 1px `--border` border, 4px radius and 16px padding. Inside a card:
  - label: 14px/600 muted
  - value: 28px/600 with `font-variant-numeric: tabular-nums`
  - unit/window: 14px/400 muted
- **Services at <600px:** the table is replaced by a `<ul>` card list. Each card holds a `<dl>` with the same grid as `.mobile-alerts dl`: 80px/1fr columns, 8px × 16px gaps.
- **Consumer lag at <600px:** the table stays a 2-column table, which fits at 375px.
- No page-level horizontal scroll at 375px, at 1440px or at 200% zoom on a 1280px viewport. Long identifiers wrap with `overflow-wrap:anywhere`.

**Charts:** none on the System page. History belongs in Grafana. No sparklines and no client-synthesised series. This removes any risk of fabricated points.

**Overview consumer-lag panel (UI-01)**
- Replaces the placeholder `<p>` with a `<section aria-labelledby="overview-lag-title">` placed after "Top rules". It holds:
  - `<h3>` "Consumer lag"
  - for admins: the per-group lag values in a 2-column `<dl>`, plus a "View system health" link → `/system`, using in-app navigation
- The panel has its own query and state, independent of the summary query. An Overview summary error must not hide lag, and a lag error must not hide the summary.

## Typography

Reused exactly: four sizes, two weights (400 / 600). No new sizes or weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / metadata / table header / badge / "Updated" time / units | 14px | 400 (metadata) or 600 (labels, th) | 1.5 |
| Body / table cells / breakdown values | 16px | 400 | 1.5 |
| Section heading (`h3`) / status headline | 20px | 600 | 1.2 |
| Page title (`h2`) / card metric value | 28px | 600 | 1.2 |

Every numeric value uses `font-variant-numeric: tabular-nums`, so refreshes do not shift layout.

**Number formatting** (`Intl.NumberFormat("en-US")`, deterministic, no locale guessing)

| Kind | Format |
|---|---|
| Rates | 1 decimal + unit (`1,234.5 events/s`) |
| Lag | integer with grouping (`12,345 records`) |
| Durations | `< 1 s` → integer ms (`245 ms`); `≥ 1 s` → 2 decimals s (`1.25 s`) |
| Ratios | percent with 2 decimals (`0.42%`) |
| Replicas | `2 / 2` |

A real measured zero renders as `0`. The client never shows `0` when the field is unavailable.

## States (System page)

Each section renders its own state from per-field availability. The page-level state machine:

| State | Trigger | Rendering |
|---|---|---|
| Forbidden | `session.role !== "admin"` (no request sent) **or** server 403 | Empty-state panel: heading + body from the copy table. No metric skeletons, no Refresh button, no Grafana link. |
| Loading | first fetch pending | `role="status"` "Loading system status…" and nothing else. No zero placeholders. |
| Error | request failed (network or 503 from query-api itself) with no prior data | `role="alert"` error text + "Retry loading system status" button |
| Metrics unavailable | 200 response with Prometheus fields marked `unavailable` | Each affected value renders the muted **"Unavailable"** badge in place of the number. Below the summary, a single notice reads "Metrics source unavailable…". Readiness from `/readyz` still renders if present. |
| Partial | some fields available, others unavailable | Available values render normally. Each unavailable one shows the "Unavailable" badge. |
| Empty | Prometheus up but no samples yet (series absent, e.g. stack just started) | Server sends `unavailable` with reason `no_data`. Value cells show the "No data yet" muted badge plus the page notice "No metrics recorded yet…". Never `0`. |
| Data | all fields available | Full layout |
| Stale | a background refetch fails while prior data exists, **or** `now − observed_at > 60 s` | Keep last values visible. Warning-pair notice "Showing data from {time} UTC. Live refresh failed." + Retry button. "Updated" time stays at the old `observed_at`. Values are never cleared. |
| Session expired | 401 | Existing global flow: stop retries and return to sign-in |

**Refresh behavior**
- `refetchInterval: 15000` while the document is visible, with `refetchIntervalInBackground: false`. One request is in flight at a time, aborted on unmount or signout.
- `retry: false`, matching existing pages.
- The query key is `["system", session.generation]`.
- The manual Refresh button is disabled while `isFetching`, using the existing `button:disabled` style.

## Interaction, accessibility and security

**Semantics and keyboard**
- Semantic `<section aria-labelledby>` per section and real `<table>`s with `<th scope>`. Metric cards are `<div>`s holding a `<dl>` (label `<dt>`, value `<dd>`), not buttons.
- Tab order: skip link → nav → Refresh → Grafana link → (stale/error Retry) → Overview link targets. Nothing in the metrics is focusable except links and buttons.
- Visible 2px accent focus ring. No focus is moved on poll or refresh.

**Live announcements**
- One polite `role="status"` region announces **only transitions**: "System status updated" after a manual refresh, "Live refresh failed" on entering stale, "Live refresh restored" on leaving it.
- Background polls that change numbers are not announced. The status headline is not a live region.

**Unavailable semantics**
- The "Unavailable" badge is text. Screen readers read, for example, "Detection delay p95, Unavailable".
- The client tests assert that `0` is never rendered for an unavailable field.

**Responsive, zoom and motion**
- Verify at 375 / 768 / 1024 / 1440px, at 200% zoom and keyboard-only.
- Under reduced motion nothing animates, beyond Phase 4's existing behavior.

**Security**
- The browser only calls `GET /api/v1/system` with the in-memory JWT and sends no query parameters or PromQL.
- The role check is server-side (403). The client-side hiding is UX only.
- The Grafana URL comes from server config in the response and renders only when it is an `http(s)` URL.

**Session**
- The query key includes the session generation.
- Signout, expiry or identity change aborts the fetch and clears the cache, using the existing session flow.

## Assumptions (user may override)

1. **⚠ System page is admin-only (prominent).**
   - The data is global, not tenant-scoped, and ingest volume leaks cross-tenant activity (05-RESEARCH Open Question 2).
   - Viewer and analyst get a server 403 and the "Admin access required" state. The nav link is hidden for them.
   - **This changes UI-01 for analysts:** the Overview lag panel shows "Consumer lag requires the admin role." instead of numbers.
   - Override option: allow analysts, and/or add a separate "operator" role. Both require backend RBAC changes.
2. Non-admins visiting `/system` see a forbidden state rather than a redirect, so deep links stay explainable.
3. 15s polling while the tab is visible and a 60s staleness threshold. Both are chosen to sit above the 5–10s lag-tracker cadence and the 1m/5m PromQL windows.
4. No charts on the System page; Grafana provides history. Phase 4's "no fabricated data" rule makes a client-side sparkline buffer undesirable.
5. No color thresholds on lag, delay or latency values.
   - Health badges derive only from readiness and replica counts.
   - Alert thresholds live in Prometheus rules (OBS-05), not the UI.
   - This avoids inventing numbers in the UI.
6. The Grafana link opens in a new tab and appears only when `SENTINEL_OBSERVABILITY.GRAFANA_URL` is configured.
7. "Degraded" means replicas up ≥ 1 but fewer than expected. "Not ready" means 0 up or `/readyz` failing.
8. Fixed service order: ingest, event-writer, detector, alert-writer, query-api. Fixed consumer-group order: event-writer, detector, alert-writer.
9. No new design tokens, dependencies or shadcn initialization. The Phase 4 design system is reused verbatim.
