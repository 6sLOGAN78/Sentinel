<objective>
Close the product half of GAP-2. Position-based lag is published by each process only for the partitions it owns. Series for lost partitions are deleted, and a SIGKILLed member's series go stale. So during the ~45 s session timeout, before the group rebalances, nobody reports the orphaned partitions, and `max by (group)` reads 0. The bench saw this (recovery 0.438 s, an artifact). The System page and Overview would show the same false 0 to an operator during a failover.

Decision (planner, within discretion): fix both product and bench. The product exports the denominator (the topic partition count) so coverage is computable from Prometheus. 05-25 makes the lag API and System report incomplete coverage as unavailable. 05-27 makes the bench measure coverage independently from Kafka offsets. Broker committed-offset lag is deliberately NOT used: the detector's committed offset is the replay pin (ADR 0012), which can trail processing by a whole window (docs/operations.md "Consumer lag").

Output: the new gauge, tests, and docs in the metric table.
</objective>
