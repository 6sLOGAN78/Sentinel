sender.py:
- `@dataclass(frozen=True) SenderConfig(urls: tuple[str,...], max_in_flight=64, retry_budget_s=15.0, request_timeout_s=10.0, max_attempts=5)` with validation: 1 ≤ urls ≤ 8, http(s) only, retry budget > 0 and < 20, max_in_flight 1..256.
- `async def run_open_loop(schedule, cfg, api_key, *, clock, sleeper, client_factory) -> ClientLog`. One `httpx.AsyncClient` per URL (timeout=request_timeout_s, no HTTP/2). Iterate the schedule lazily. For each batch compute due = t0 + offset_ns, `await sleeper(max(0, due − clock()) / 1e9)`, then `asyncio.create_task(_send(batch, due, ...))`.
- `_send` acquires an asyncio.Semaphore(max_in_flight). It records sent_ns after acquire, serializes once via send._serialize_batch and posts with header X-API-Key. On 202 it calls send._validate_accepted. On 429/503/transport error it waits max(Retry-After, jittered fallback) within the remaining budget and reuses the same bytes. On 4xx other than 429 it records rejected.
- Bounded memory: completed tasks are discarded via `asyncio.wait`/done callbacks. Request records are kept as compact tuples. 1M events / 200 = 5,000 records, which is fine.
- Record harness CPU% via `time.process_time()` deltas per 10 s as harness_cpu_percent_max.

sse.py:
- `async def subscribe_alerts(base_url, token_provider, stop: asyncio.Event, *, clock, client_factory) -> list[Arrival]`. GET /api/v1/alerts/stream with Authorization: Bearer <token> and Accept: text/event-stream. Parse frames line-by-line (`id:`, `event:`, `data:`, blank line = dispatch). Read continuously. On EOF or error, reconnect with Last-Event-ID = last id and bounded backoff 0.5-5 s with jitter.
- token_provider is `Callable[[], Awaitable[tuple[str, int]]]` returning (token, expires_at_ns). The token is refreshed when < 60 s remain.
- Never log or store the token.
- Dedupe by alert_id.

rawlog.py:
- `id_digest(ids: Iterable[str]) -> str` (16-hex).
- `client_section(log, schedule) -> dict` with exactly the RAW_FORMAT client keys.
- `sse_section(arrivals, plan) -> dict` maps arrivals to trigger intended times using the attack plan's (rule, entity, window) → trigger batch intended_ns.
