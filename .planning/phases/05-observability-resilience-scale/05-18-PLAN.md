## Phase Goal

**As an** operator, **I want to** see pipeline health and have failure and scale behavior proven by tests and a reproducible benchmark report, **so that** reliability and performance are demonstrated rather than claimed.

<objective>
Implement benchmark scenario execution and measurement collection, wire `make bench` and extend report.py with the overload checks. After this plan, a single command produces a reconciled report (or a refusal) from a real run. The real run itself happens in 05-20 (it needs the user to free disk).

Purpose: BENCH-01 (`make bench`), BENCH-02 (≥ 1M accounting inputs), BENCH-04 (detector kill + recovery inputs) and REL-04 (overload scenario in multi-replica Compose).
Output: scenarios, collectors, the run subcommand, the overload equations in report.py and the RAW_FORMAT update, tests, and the Makefile `bench` target.

Measurement definitions follow 05-RESEARCH Patterns 9-11 exactly:
- Recovery time = t_recovered − t_kill, where t_recovered is the first time max detector-group lag stays ≤ the pre-kill p95 baseline for 30 s. Bounded timeout: 10 min.
- Persistence latency uses SSE arrival as an upper bound (no migration 009; assumption, user may override).
- The benign mix includes auth.failure unless the capacity preflight refuses. If it refuses, the run stops with the preflight numbers instead of silently changing the mix.
</objective>
