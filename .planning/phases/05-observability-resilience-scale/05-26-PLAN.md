<objective>
Close GAP-3. During bench-up of run 20261119a, detector-3 exited 2 s after start, before any load, with `postgres decision invariant or transaction failed`. That was followed by "background worker failed" and "shutdown incomplete". Docker restarted it (RestartCount 1) and it then ran healthy. `DetectionDecisionStore.transaction` (detection_decisions.go:129) replaces every error from the transaction body with that one string, so the logs cannot tell which case occurred.

Likely hypothesis, to be confirmed only by reproduction: the third member joining causes a rebalance while an earlier-generation assignment is still running Register/PrepareRestore. The fence check returns "stale detector assignment" (newer generation already registered), or a concurrent fence insert hits lock_timeout. Either path reaches `DetectorConsumer.fail`, which ends the process. Alternatives the diagnosis must rule in or out: a lock_timeout/serialization/deadlock SQLSTATE, a frontier mismatch on a fresh group, or a genuine invariant bug.

Locked-decision flag: ADR 0007 says "Terminal restore failures must reach the process lifecycle, not retry indefinitely while ready" and "fail closed on ... ownership loss". Turning superseded ownership into a partition-level non-terminal event, or adding a bounded transient retry, reinterprets that text. Task 2 is therefore a blocking decision checkpoint for the user. The orchestrator relayed a preference ("if benign by design, make it a clean retry rather than a crash"), but only the user can approve an ADR 0007 amendment.

Output: classification, reproduction, user decision, fix and ADR note.
</objective>
