## Phase Goal

**As an** operator, **I want to** see pipeline health and have failure and scale behavior proven by tests and a reproducible benchmark report, **so that** reliability and performance are demonstrated rather than claimed.

<objective>
Build the refuse-on-mismatch benchmark report first, so every later harness piece targets a fixed, tested raw contract. `bench/report.py` reads one raw-run JSON file (format_version 1) and recomputes the spec §12 / RESEARCH Pattern 9 reconciliation equations. On success it writes the Markdown/JSON report. On any mismatch it writes only a FAILED diff and exits nonzero.

Purpose: BENCH-03 (report contents plus refusal) and the BENCH-02 reconciliation logic. The bench run in 05-20 can never "claim" a number this script did not compute from raw measurements.
Output: report.py (stdlib only), RAW_FORMAT.md contract, pytest suite with a reconciled fixture and mismatch fixtures. Fixtures are clearly test data and are never written to benchmarks/results.
</objective>

  <action>
Implement `bench/report.py` with the shebang `#!/usr/bin/env python3`, a docstring and `from __future__ import annotations`. Use only the stdlib: json, argparse, hashlib, statistics is not needed, datetime, pathlib, os, sys.

CLI: `report.py --raw PATH --out DIR [--selftest]`.

Structure:
- `class ReportError(Exception)` with display-safe messages.
- `load_raw(path) -> dict` validates format_version==1 and required keys. Unknown extra keys are allowed but listed in limitations.
- `reconcile(raw) -> list[Failure]` implements every RESEARCH Pattern 9 equation. Each Failure has an id, a human message and expected/observed values.
- `percentile(sorted_samples, q)` uses the nearest rank.
- `histogram_quantile(buckets_before, buckets_after, q)` uses Prometheus-style linear interpolation within the bucket and reports the bucket bounds as resolution.
- `sustained_rate(requests)` gives 10 s accepted-event windows, returning p50/p95.
- `recovery(raw)` implements the Pattern 11 definition.
- `render_markdown(summary) -> str` emits sections Hardware, Configuration, Workload (event size distribution, total events, run duration, input rate), Throughput, Latency (ingest CO-corrected + service time, detection, SSE notification, API p95), Resources, Consumer lag and recovery, Loss and duplicates, Rule hits (expected vs observed), Limitations (always non-empty; includes the persistence-latency note that SSE arrival is an upper bound because there is no wall-clock persistence column, and "generator saturated" when slip p99 > 1000 ms), and Reproduction (git_sha, image_tag, exact make command).

Output names:
- On success write `<YYYY-MM-DD>-<scenario>.md` and `.json` (date taken from run.started_at UTC, not wall clock) with 0644.
- On failure write only `<date>-<scenario>.FAILED.json` and exit 1.

Refuse:
- provenance=="fixture" when the resolved --out path is the repo `benchmarks/results` directory → exit 2, no files written.
- --out outside the repo with provenance measured is allowed (used by tests with a measured-copy mutation).
- Never overwrite an existing report file: exit 3.

`--selftest` copies the bundled reconciled fixture path (resolved relative to the repo root: generator/tests/fixtures/bench_raw_reconciled.json) into a TemporaryDirectory, runs it and asserts success.

No numbers are hardcoded in the template other than the format constants (1,000,000 floor, 30 s stable window default, 100-sample p99 floor), each defined once as a named constant.
