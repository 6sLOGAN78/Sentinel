## Trust Boundaries

### Root-owned readiness closeout delta

After the original independent audit, the final hosted repeat exposed a response-deadline gap during Kafka outage. Root rechecked T-02-09-1/2/3 against the bounded-worker repair; this is an explicitly inline delta assessment, not a new independent 90-threat audit. Sanitized states/default binds/draining are unchanged. One worker per admitted request retains its semaphore slot until work truly finishes, limiting stuck dependency calls to sixteen. HTTP response timeout/cancellation is independent of that worker; result buffers are bounded by the trusted check list, no mutable response map crosses goroutines, and late success cannot override deadline failure. Panic recovery closes the result channel and returns the slot without exposing panic content. Saturation, liveness, release/recovery and panic cleanup have race-enabled regression coverage. The original synchronous-check line references below describe the prior audited revision; this delta supersedes that mechanism without creating a new risk acceptance.

| Boundary | Description | Data crossing |
|----------|-------------|---------------|
| HTTP client → shared middleware and listeners | Origin, headers, paths, bodies and TCP peer identity meet explicit bind and logging policy | Untrusted request data; API-key secret |
| Operator/key files → PostgreSQL/verifier | Provisioning and credential verification resolve trusted tenant and scopes | Raw secret only at creation/private delivery; stored SHA-256 hash |
| Verified intake → Redis/Kafka | Authenticated key ID governs event quota; complete validated batches require durable acknowledgement | Tenant-bound canonical events and stable IDs |
| Kafka → writer → ClickHouse/DLQ → offsets | Untrusted records acquire durable effects before partition-contiguous source commits | Event payloads, poison context and origin metadata |
| Verified query identity → native SQL | Only the authenticated tenant and validated event UUID enter bound lookup parameters | Tenant-scoped event history |
| Operator configuration → migration/topic policy | Validated TTL and explicit quoted topic policy update existing resources | Retention settings and immutable schema history |
| Ops requests → live clients | Separate listener uses bounded protocol checks and draining state | Named health states; dependency errors remain internal |
| CLI/env/output paths → generator/seed filesystem/network | Private credentials, bounded sends, exact-run manifest and descriptor-relative writes | API key; pseudonymous synthetic events; nonsecret run IDs/totals |
| Local filesystem/build tags → Docker/CI | Context exclusions run before transfer; both dependency graphs and causal test groups are policy inputs | Source, dependency pins; private material excluded |
| Local execution → completion metadata | Recorded command exits do not imply hosted CI success or erase original findings | Sanitized acceptance and independent review evidence |
