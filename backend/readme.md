# Backend Structure

```txt
.
├── cmd/
├── internal/
├── static/
├── go.mod
├── go.sum
├── .golangci.yml
├── Taskfile.yml
└── README.md
```

---

# Folder & File Explanation

## `cmd/`

This folder contains the application entry points.

Usually each executable application has its own folder inside `cmd`.

Example:

```txt
cmd/
 └── sentinel/
      └── main.go
```

---

## Why We Use `cmd/`

This keeps application startup logic separated from business logic.

The `main.go` file usually handles:

- application startup
- dependency initialization
- configuration loading
- server startup

---

## `internal/`

This folder contains the private application code.

Example:

```txt
internal/
 ├── api/
 ├── database/
 ├── service/
 ├── middleware/
 └── config/
```

---

## Why We Use `internal/`

Go's `internal` package system prevents external projects from importing private application code.

This helps enforce clean architecture boundaries.

---

## Typical Things Inside `internal/`

### API Layer

Handles:

- HTTP handlers
- routes
- request/response logic

---

### Service Layer

Contains business logic.

Example:

- authentication
- payments
- user management

---

### Database Layer

Handles:

- queries
- repositories
- migrations
- transactions

---

### Middleware

Handles:

- logging
- authentication
- rate limiting
- request processing

---

# `static/`

Contains static assets.

Examples:

- images
- HTML files
- CSS
- JavaScript
- uploads

---

## Why We Use `static/`

Useful when backend serves frontend assets or public files.

---

# `go.mod`

Main dependency configuration file for Go modules.

Defines:

- module name
- Go version
- dependencies

Example:

```go
module github.com/6sLOGAN78/sentinel
```

---

## Why `go.mod` is Important

It enables:

- dependency management
- reproducible builds
- version tracking

---

# `go.sum`

Stores checksums for Go dependencies.

Automatically generated by Go.

---

## Why `go.sum` is Important

Ensures:

- dependency integrity
- security
- reproducible installations

Go verifies downloaded packages using these checksums.

---

## Why We Use `.golangci.yml`

---

# `Taskfile.yml`

Configuration file for Task.

Task is a modern task runner similar to:

- Makefile
- npm scripts

Used to automate development workflows.

---

# Why We Use Taskfile

Instead of remembering long commands:

```bash
go run ./cmd/sentinel
```

we can simply run:

```bash
task run
```

This improves:

- developer productivity
- consistency
- automation

---

# Understanding Your Taskfile

---

# Version

```yaml
version: '3'
```

Taskfile schema version.

---

# Variables

```yaml
vars:
  SENTINEL_DB_DSN: '{{.SENTINEL_DB_DSN | default ""}}'
```

Defines reusable variables.

`SENTINEL_DB_DSN` stores the database connection string.

---

# `help`

```yaml
help:
```

Displays all available tasks.

Run:

```bash
task help
```

---

# `confirm`

```yaml
confirm:
```

Creates a confirmation prompt before dangerous operations.

Example:

```txt
Are you sure? [y/N]
```

Used before database migrations.

---

# `run`

```yaml
run:
```

Runs the backend application.

Command executed:

```bash
go run ./cmd/sentinel
```

Run using:

```bash
task run
```

---

# `migrations:new`

Creates a new database migration file.

Example:

```bash
task migrations:new name=create_users_table
```

This generates migration files inside:

```txt
internal/database/migrations
```

---

# Why Database Migrations Matter

Migrations help manage database schema changes safely.

Examples:

- creating tables
- adding columns
- updating indexes

---

# `migrations:up`

Runs all pending database migrations.

Command:

```bash
task migrations:up
```

Uses:

```bash
tern migrate
```

to update database schema.

---

# `tidy`

Automates Go dependency maintenance.

Runs:

```bash
go fmt ./...
go mod tidy
go mod verify
```

---

## What These Commands Do

### `go fmt`

Formats Go code automatically.

---

### `go mod tidy`

Removes unused dependencies and adds missing ones.

---

### `go mod verify`

Verifies downloaded dependencies are correct and unmodified.
